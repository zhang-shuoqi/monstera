# Monstera 总纲 · 界面宪法与模块地图

> 版本：v1.0 ｜ 效力：最高。任何代码、UI、文案与本总纲冲突时，以本总纲为准。
> 适用人：Monstera 唯一所有者（非技术背景），以及所有被雇佣的 AI（DeepSeek / 豆包 / Kimi / Trae / 任何后来者）。
> 使用方式：任何 AI 接到任务时，必须先读本文件，再读任务书。开工前用「变更申报单」声明动哪个坑。

## 第一编 · 宪法（六条，不可违背）

**信条**：别人做直播，Monstera 做档案。

1. **本地主权**：数据、密钥、日志、界面资源全部在本机。禁止引入需要联网加载的 UI 资源、账号体系、遥测。
2. **证据封存**：Agent 做过的一切必须可回放、可审问。封存要完整到无聊（Newton 条款：核心承诺 flawless 才算数）。
3. **叙事与调试严格隔离**：聊天流只说人话；一切原始载荷（JSON、参数、堆栈、内部事件名）只在执行面板、且默认折叠。
4. **反表演**：数据可以实时，呈现必须静态；运动只合法于状态真实变更的瞬间。灯塔不是舞台。
5. **权重守恒**：强信息大字白字，弱信息小字灰字；折叠是默认，展开是用户动作；注意力是货币，只在用户必须驻足处花费。
6. **不讨好**：不道歉、不祝贺、不卖萌、不用感叹号。失败 = 事实 + 出路。

**第七信条 · 成本原则**：成本归机器，判断压到一次点击，人话说到最浅。
**第八信条 · 三时刻**：瞥见免费，离开自由，回溯可达。看与不看是用户的权利；原始层是地基不是门面。

**小白三铁律（终稿）**：
1. **永远默认 L1**：每个区域先是一句小学生能懂的话；深层藏在不吓人的「详情」后
2. **行动时刻必须人话**：凡出错或等你决定，必须给「发生了什么 + 为什么（一行）+ 一个解决动作」；常规状态用诚实标签（推进中/等你确认/疑似卡住），不拟人、不糊弄
3. **每个动作不超过点一下**：错误就地解决（一个主动作，备选折叠）；换手不设按钮——把自家错误讲清楚就是最好的防换手

**决策过滤器**（任何新增/修改过此四问）：
- Q0：这是不是这个时代的默认答案？是 → 放弃或改写到认不出出处
- Q1：它服务哪种用户焦虑？说不清 = 装饰，禁止进门
- Q2：与宪法冲突吗？冲突即弃
- Q3：能用 Monstera 自己的视觉语言（透明度权级/留白/金绿红状态语义）表达吗？

**总判据**：拿掉"反骨"叙事后，用户是否仍立刻获得别家给不了的东西？（Segway 测试）

## 第二编 · 产品地图（三大区域，职责终身切割）

### 区域 A · 侧栏（导航层）
- **职责**：切换与回溯。用户在这里"选去哪"，从不在这里"看过程"。
- **模块清单**：
  - A1 新对话按钮 ｜ A2 模式切换（agent/ask）｜ A3 侧栏入口 ｜ A4 历史折叠区（对话/任务两个）
- **禁止**：任何执行过程、任何原始信息、任何动画（入场动画除外）

### 区域 B · 聊天内容框（叙事层）
- **职责**：讲清楚"目标是什么、结论是什么"。
- **内容白名单**（只许这五种出现）：
  - B1 用户目标（右对齐 + 头像）
  - B2 模型正文/结论（左对齐，无气泡直排）
  - B3 过程摘要 chip（一行，人话，默认折叠，展开是用户动作）
  - B4 终态卡（全界面唯一实体卡：绿/红细边 + 图标 + 事实与出路）
  - B5 live 条（sticky，静默指示"正在执行"，稳定点，无脉冲）
- **内容黑名单**（出现即违规）：原始 JSON、工具参数、报错堆栈、内部事件名、裸 API 错误、工具内部名（file_write 必须显示为"写入文件"）
- **翻译表**：所有底层事件进白名单前必须经"事件 → 人话摘要 + 图标 + 状态色"映射，映射表集中维护（代码章节 ch06）

### 区域 C · 执行面板（卷宗室 / 调试层）
- **职责**：封存与调阅。叙事层不说的细节全在这里，默认折叠，随取随查。
- **模块清单**：
  - C1 计量条（台账：步数/工具/耗时/tokens/费用，静态小字）
  - C2 轮次卷宗（第N轮编号 + hairline + 一档背景面差 + 头部一行摘要；折叠默认）
  - C3 证据块（每轮展开内含：改了哪些文件 diff + 执行了哪些命令 + 命令输出；Codex 证物袋模式）
  - C4 静默航标（当前轮高亮 = 纯色细条 + 一档背景差，无发光无脉冲；可点击定位到 B 区消息，反之亦然）
  - C5 终止区（footer：重试/状态陈述；interrupted 单独分支："任务已被中断"而非"失败"）
- **禁止**：仪表盘语言、实时跳动的数字、庆祝动画

### 区域间接口（只许这三个）
- 接口 I1：B→C 定位（点消息跳对应轮次）
- 接口 I2：C→B 定位（点轮次跳对应消息）
- 接口 I3：B5 live 条与 C4 航标状态同源（永远一致）

## 第三编 · 组件原语库（所有交互只许用这六个，禁止另造）

> 原语是"坑的模具"。现状的三种折叠、两种截断、25+ 处散装 toast 全部收敛至此。

| 原语 | 职责 | 铁律 |
|---|---|---|
| P1 Fold | 一切折叠/展开 | 状态可持久化；展开态必须活过 SSE 帧重建；折叠态显示摘要而非原文首行 |
| P2 Truncate | 一切长文本 | 单一策略：N 字截断 + 省略号 + 悬浮完整；详情区全量仅一处（证据块） |
| P3 Toast | 一切轻提示 | 必须走统一调度（队列/去重），禁止散装调用 |
| P4 ScrollRegion | 一切滚动区 | 自带滚动主权（用户上翻停跟随 + 回到底部入口）；agent 区与聊天区同一实现 |
| P5 Meter | 计量呈现 | 静态陈述，数字跳动禁止上屏 |
| P6 TurnBox | 轮次容器 | 档案盒规格：编号 + hairline + 背景差 + 头部摘要行 |

视觉 token（颜色/字阶/留白四档节奏）沿用现有 CSS 变量，不动。

## 第四编 · 代码章节制（解决"不知道改哪里"）

### 目标文件结构（无构建步骤，浏览器直跑）

```
Monstera/
├─ index.html            # 骨架 + 三大区域挂载点（<300 行）
├─ css/
│  ├─ ch01-tokens.css    # 宪法第五条的视觉语言（现有 token 原样迁移）
│  ├─ ch02-layout.css    # 三区域布局
│  ├─ ch03-primitives.css# P1-P6 原语样式
│  └─ ch04-regions.css   # 各区域模块样式
├─ js/
│  ├─ ch10-core.js       # 状态层（Alpine store：会话/任务/运行态唯一数据源）
│  ├─ ch11-primitives.js # P1-P6 原语实现
│  ├─ ch12-sidebar.js    # 区域 A
│  ├─ ch13-chat.js       # 区域 B（叙事层 + 翻译表调用）
│  ├─ ch14-agentpane.js  # 区域 C（卷宗室）
│  ├─ ch15-stream.js     # SSE/流式 + 渲染调度（增量更新，禁止全量重建）
│  └─ ch16-legacy.js     # 迁移期临时收容所，迁完即删
├─ vendor/alpine.min.js  # 本地 vendor（本地主权，禁止 CDN）
└─ 总纲.md（本文件）      # 永远放在项目根目录
```

### 施工纪律
1. 每个文件头必须写注释：`// 本文件对应总纲：第X编 区域X / 原语PX`，与该文件无关的代码禁止入内
2. **变更申报单**（任何 AI 开工前提交）：
   ```
   任务：____
   动哪个文件（章节）：____
   动哪个模块/原语（坑位）：____
   是否新增坑位：是/否（是 → 必须先更新第五编插槽表）
   预计触碰行数：____
   ```
3. 一个任务只许动申报的章节；发现必须越界时，停下汇报，不许顺手改
4. 每章完工标准：该章的旧实现从 ch16-legacy.js 中删除，文件行数回落

## 第五编 · 功能插槽登记表（一个萝卜一个坑）

### 已占用坑（现有功能，迁移时一一对应）
S1 新对话 ｜ S2 模式切换 ｜ S3 历史区 ｜ S4 消息流 ｜ S5 终态卡 ｜ S6 live条 ｜ S7 计量条 ｜ S8 轮次卷宗 ｜ S9 证据块 ｜ S10 设置齿轮 ｜ S11 无模型引导卡

### 预留坑（已划定位置与边界，未来功能只准填这里，不许另开新区域）
| 坑位 | 名称 | 位置 | 边界 |
|---|---|---|---|
| R1 | 计划视图 | 区域 C 顶部、计量条之下 | 只陈述意图与步骤状态，不重复叙事层内容 |
| R2 | 记忆面板 | 区域 A 内折叠区 | 只读 + 删除，禁止编辑入口（先封存后操作） |
| R3 | 技能/工具配置 | 设置齿轮展开区 | 纯配置表单，禁止运行态信息混入 |
| R4 | 多模型对比 | 区域 B 终态卡之下的专用容器 | 结论先行，对比细节默认折叠 |
| R5 | 本地证据检索 | 区域 C 顶部检索条 | 全局检索证据原文，结果定位到轮次 |
| R6 | 归档/导出 | 区域 A 历史条目右键 | 导出为通用格式（md/json/zip） |

**铁律**：新功能诞生流程 = 先在登记表开坑（定位置定边界）→ 总纲更新 → 才许施工。不许先写代码再补坑。

## 第六编 · AI 协作章程（一人 + 多 AI 的工作法）

1. **开工仪式**：任何 AI 接到任务，第一步读总纲，第二步提交变更申报单，第三步才许碰代码。
2. **三段式任务书**：调研（只报事实+文件:行号）→ 方案（只写图纸不写码）→ 施工（只动申报章节）。三段不许合并。
3. **单 AI 单任务**：一个任务只交一个 AI；多 AI 并行时按章节隔离，绝不允许两个 AI 同时动同一章。
4. **验收双签**：施工完成后，换一个 AI 按任务书验收（原施工 AI 不许自验）。
5. **宪法仲裁**：AI 间意见冲突时，不辩论，回到总纲第一编逐条对照；对不上就升级到主人裁决。
6. **禁令**：擅自新增依赖、擅自开新区域/新坑、跨章顺手修改、删除总纲——一律返工。

## 第七编 · 施工总计划（五卷工程）

> 原则：先骨架后血肉，先机制后视觉。每卷完工跑全局验收才许开下一卷。

- **第一卷 · 骨架工程**：搭建第四编文件结构 + Alpine 接入（本地 vendor）+ 状态层 ch10（会话/任务/运行态唯一数据源）。像素不动，行为不变。验收：页面与现在完全一致，但事件流驱动 ch15 增量渲染（不再有全量 innerHTML 重建）。
- **第二卷 · 原语工程**：实现 P1-P6 六个原语，把现状三种折叠/两种截断/散装 toast/双标滚动全部替换收敛。验收：全项目折叠走 P1、截断走 P2、toast 走 P3、滚动走 P4——grep 不到旁路实现。
- **第三卷 · 卷宗化视觉**：轮次卷宗化（P6）、静默航标、去表演清算、泄漏翻译表落地、死代码（tv-* 系）删除。验收：Segway 测试 + 3 秒锚点测试通过；静置 30 秒无任何循环动画。
- **第四卷 · 证据呈现**：证据块（C3）、B↔C 互定位（I1/I2）、中断语义分支、折叠状态记忆。验收：随机抽历史任务，只看界面能完整追溯"它基于什么、做了什么、结果如何"。
- **第五卷 · 微观层**：hover 补全、空态文案、复制按钮归位、文案边缘修正（"敬请期待"/裸词"backend"）。

### 全局验收（每卷必跑）
1. Segway 测试：不知情用户 5 分钟，第一句话落在「安静/清晰/能查证」
2. 3 秒锚点测试：10+ 轮任务滚走后 3 秒内找到当前轮
3. 宪法自查：Q0-Q3 四问 + 总判据

## 第八编 · 常态化体检表（每卷交付时对照，由验收 AI 执行）

- E1 聊天流黑白名单扫描（黑名单出现 = 不合格）
- E2 动画运行时盘点（循环动画出现 = 不合格）
- E3 滚动主权双区测试
- E4 折叠持久化抽查（切任务往返）
- E5 文案语气抽查（感叹号/道歉/祝贺 = 不合格）
- E6 变更申报单与代码实际 diff 一致性（越界 = 返工）
- E7 视觉验收：每片验收附真实任务运行截图，逐区对照九幕矩阵；布局改动附窄窗（≤1100px）截图一张；勘察三问（空白态/任务态/拉窄+第一眼感受）作为第二战役基线存档。
