# 附录 B · 施工方法核验与修正案

> 隶属：《Monstera 总纲》第七编修正。开工前施工 AI 必读。
> 核验日期：2026-09。依据：微软架构库 Strangler Fig 模式、Fowler 原著、shadcn/ui Message Scroller、GitHub 同类 issue 实践。

## B.0 修正总述

《总纲》第七编"五卷工程"**顺序修正**：新增「第零卷」，第一片迁移目标改为最小切片。
原因：Gartner 统计 70% 重写失败或超期；绞杀榕模式（微软官方收录）要求"先易后难、每片闭环"。
大改 = 范围大（全书五卷照走）；方法 = 绞杀式（每卷拆片，片间可验收可回滚）。

## B.1 第零卷 · 行为基线工程（最先做，不动一行代码）

目的：改造前把"现在长什么样"钉死，作为每一片迁移的对比标尺。

1. **录屏基线**：用系统录屏，完整操作一遍下列 10 个黄金场景（每段 ≤2 分钟）：
   S1 打开应用空白态 → S2 发起一次对话（ask 模式）→ S3 流式回答中上翻阅读再回底
   → S4 发起 Agent 任务 → S5 执行中展开一个过程 chip → S6 执行中上翻被拉回（记录这个 bug 现状）
   → S7 任务成功终态 → S8 手动停止 → S9 刷新页面恢复任务 → S10 切换历史会话
2. **场景清单**：把上述 10 条写成 checklist 存为 `docs/黄金场景.md`，每条注明"当前预期行为"
3. **验收规则**：每迁移一片，重跑相关场景录屏，与基线对比——旧行为该保留的分毫不动，新行为符合全书分镜
4. 文件存入项目 `docs/` 目录（该目录从此常设）

## B.3 绞杀榕三铁律（写入章程，违者返工）

1. **每片闭环**：transform（新实现）→ coexist（新旧并行可切换）→ eliminate（旧实现删除）。
   切换开关：`window.MONSTERA_CH = { chatScroll: true, ... }`，新实现注册自己，入口按开关路由。
   好处：任一片出问题，关开关即回滚，爆炸半径 = 一片。
2. **ch16-legacy.js 单调递减**：每次交付必须报告该行数，只许减不许增；
   每章迁完做"退役仪式"：全库 grep 旧实现零引用 → 删除 → 申报关闭。
   警示（Knight Capital 案例）：死代码与死开关是定时炸弹，绝不允许"先留着以后再说"。
3. **新功能只进新代码**：任何新功能禁止写进 ch16-legacy 管辖的旧实现里。

## B.4 P4 滚动主权技术细则（照抄施工）

- 双区（聊天流 / 执行面板）共用同一实现，禁止两套逻辑
- 阈值：贴底判定 60px（现有值，保留）
- 用户上翻 → 立即置 lock 标志，**锁一直持续到用户回到底部或点击"回到底部"**；
  禁止"内容增长重新触发跟随"（OpenClaw issue 教训：增长不得重置用户意图）
- 两个滚动容器 CSS 加 `overflow-anchor: none`（防浏览器滚动锚定与脚本打架；
  注意 Safari 不支持该属性——脚本判断必须完整自给，不得依赖浏览器行为）
- 暂停期间新内容到达 → 显示浮动"回到底部"按钮（11px，34% 灰，胶囊）；
  用户回到底部 → 按钮消失、跟随恢复（shadcn Message Scroller 同款语义）
- 验收：流式/执行中上翻，连续 30 帧不被拉回；回底后跟随恢复

## B.5 可行性核验结论（本书行为逐项）

| 全书条目 | 判定 | 依据 |
|---|---|---|
| P4 滚动主权 | ✅ 有业界标准模式 | shadcn/ui Message Scroller 2026；ChatGPT/Claude 同款行为 |
| P1 折叠保活 | ✅ Alpine :key + dataset 模式 | :key 保证未变元素状态保留（Alpine 官方讨论 #570） |
| P3 Toast 调度 | ✅ 普通队列实现 | 无技术障碍 |
| P6 轮次卷宗 | ✅ 常规 DOM | 无技术障碍 |
| B5/C4 航标 sticky | ✅ CSS position:sticky | 无技术障碍 |
| I1/I2 互定位 | ✅ scrollIntoView + 一次性闪烁 | 全书已规定闪烁仅 .3s 一次性 |
| 证据块 diff | ✅ 纯 DOM 渲染 | Codex CLI 同款信息结构 |
| 动效白名单 | ✅ CSS 类切换 | x-if 不支持过渡的坑已在附录 A 规则三规避 |

**结论：全书无一条存在技术不可行项。**
