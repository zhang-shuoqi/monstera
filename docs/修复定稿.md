## 定稿 一 · 历史任务列表冷启动返空

**触碰 agent_core/：是**（`state_store.py` 在内核目录）。

**症状**：进程冷启后、首查 `GET /api/agent/tasks` 返回 `[]`，尽管 `backend/agent_data/index.json` 存有 20 条历史任务；过段时间（触发 restore 种子化后）又返回 20。早前台瞬态复现一次，现已自愈——但属时序脆弱点。

**根因**：
- `list_tasks()`（backend/routers/agent.py L315-318）→ `_core().history_rows()`（runtime.py L273-274）→ `state_store.index_rows()`（state_store.py L342-344）返回**内存 `self._index`**，不读取持久 `index.json` 文件。
- `_index` 启动值为 `[]`（state_store.py L131），仅在 `restore()→_rebuild_index()`（L300-314/336，由 `AgentCore.__init__` L139 调用）或逐任务 `_sync_index`（L321）时填充。
- 若 `restore()` 未在首查前完成磁盘数据种子化（进程重建/异常启动时序），`_index` 为空 → 端点返空，尽管磁盘有数据。

**方案（二选一，倾向 A）**：
- **A（推荐）**：`index_rows()` 在返回前若内存 `_index` 为空，则直接从持久 `index.json` 文件（`self._index_path`）读回并填充内存索引；即"以磁盘为准兜底"。不改路由/前端接口结构。
- B：把"调用 `restore()`"从 `AgentCore.__init__` 改为在任意读路径（`index_rows`/`get_task`）前惰性确保执行一次（幂等，`_seeded` 标记）。

**触碰面**：仅 `backend/agent_core/state_store.py`（+ 可选一行 runtime/agent 路由）。不改事件结构/状态机/工具。

**冻结例外理由**：真实用户场景（冷启动看历史任务为空）的可复现防空问题；方案为读路径幂等兜底，不新增模块/参数/事件；改动面最小。

**测试（改前后都跑）**：
- 改前与改后各跑：`backend/_p5_smoke.py`、`backend/_p6_features_smoke.py`、`backend/_p7_acceptance.py`（v1.0 契约不破坏）。
- 针对性：冷启动（新进程）首查 `/api/agent/tasks` 返回磁盘真实条数；已存在的 `index.json` 不丢、不重复、排序一致；运行期新建任务的 `_sync_index` 仍正常。

## 定稿 二 · 文件证据缺统一 diff 字段

**触碰 agent_core/：是**（`toolbox/fs_tools.py` 在内核目录）。

**症状**：C3 证据块的"文件证据 → 展开 +行/−行 diff"无法呈现——`file_edit` 只回 `summary`+bytes，`file_write` 只回 `mode`+bytes，`TOOL_RESULT_RECEIVED.data` **无统一 diff**。前端受红线1约束只能显示真实 summary/字节，diff 缺失。

**根因**：
- `backend/agent_core/toolbox/fs_tools.py`：`FileEditTool.execute` 回 `{path,mode,replaced,summary,bytes}`；`FileWriteTool.execute` 回 `{path,mode,created,overwritten,bytes}`。均未生成统一 diff 文本。

**方案**：
- 在 `file_edit`/`file_write` 的产出 `data` 中**增补可选字段 `diff`**（统一 diff 纯文本，`+ 行`/`− 行`/上下文，供前端 C3 渲染，P2/52vh 限高由前端截断）。
  - `file_edit`：由 `old_string`/`new_string` 生成该片段级 diff（或整文件 diff），字段名 `diff`。
  - `file_write`：created 时整文件作为 `diff` 的可选 precursor（或仅对 overwritten 生成 diff）。
- **契约注意事项**：`diff` 是 `data` 内**新增可选键**，不改变事件类型顺序、不改 `ToolResult` 协议、不新增工具。旧事件无 `diff` 时前端已按红线1降级（现行为），保持向前兼容。
- 前端依据 `data.diff` 存在与否走 C3 diff 或降级（已是现状）。

**触碰面**：`backend/agent_core/toolbox/fs_tools.py`（两个 execute 产出加字段）+ 可选前端 `buildEvidence` 读 `d.diff`。（后端是必需品；前端为配套。）

**冻结例外理由**：C3 终稿规格（审问完全追溯）真实缺口；方案是给既有工具结果**加可选数据字段**，不新增工具、不改事件顺序、不碰状态机/路由契约；改动收敛于两个工具函数。

**测试（改前后都跑）**：`_p5/_p6/_p7` 三脚本回归；`_p6` 的 file_edit 行为用例需确认 summary/bytes 仍真、新增 `diff` 存在且与 old/new 一致；后端模拟跑一次 file_edit/file_write 断言 data.diff 字段；前端渲染含 diff 的证据行不回归现有降级路径。

## 定稿 三 · 停止语义漂移

**触碰 agent_core/：是**（状态持久化 `state_store.py`/`TaskState`）+ 前端 `ch16-legacy.js`。agent_core 部分走冻结例外。

**症状**：同一次用户手动停止，三处文案不一致——聊天流实时快照「任务已被用户中止」，执行面板顶部「失败」，刷新/重拉后聊天流变「任务执行失败」。

**根因（已定位证据链）**：
1. 后端 `_task_snapshot`（backend/routers/agent.py L203 附近）只在 `status=='failed'` 时计算 `meta.terminate_kind`，且**不持久化**（tasks/*.json 无 meta）。
2. 任务列表/详情接口返回 `to_dict()` 裸对象，不含 `meta`。
3. 前端执行面板顶部读 `task.status` 映射「失败」，不看 `meta.terminate_kind`。
4. 聊天流终态卡只在实时快照阶段能读到 `meta.terminate_kind==='user_interrupt'`（→「中止」），刷新/重拉后丢失 → 回退「任务执行失败」。

**方案**：
1. **持久化**：把退路 kinds 落盘——`TaskState` 增持久字段（如 `terminate_kind`，取值 `user_interrupt`/`plan_denied`/`max_iterations`/`max_tool_calls`/`timeout`/`error`/`interrupted`），由**状态终态写入路径**（StateProjector 是唯一状态机/落盘维护者，铁律不破坏）随 `tasks/*.json` 一并持久化。
2. **统一读取字段**：任务列表/详情接口的返回统一带上 `terminate_kind`；前端执行面板顶部、聊天流终态卡、重拉路径**一律读同一字段**（存在则用，否则回退 status），消除"实时 vs 重拉"分歧。
3. **文案归口**：前端把 `terminate_kind` 映射为终态文案（中止/被拒/达上限/超时/失败/中断），失败类渲染单点归口。
4. **注意**：不得改事件顺序；不得绕开 StateProjector 的写状态唯一入口（沿用既有 task_failed_event 工厂）。

**触碰面**：`backend/agent_core/state_store.py`/等处（持久化字段）+ `backend/routers/agent.py`（返回带 terminate_kind）+ 前端 `js/ch16-legacy.js`（统一读取与文案）。历史遗留任务无该字段 → 前端按 status 回退，向前兼容。

**冻结例外理由**：真机亲测的**信任级 bug**（用户停止却见「失败」）；已与近期设计讨论对齐（记忆存档、验收 AI 已核根因）；方案是"持久化一个既有判定的枚举 + 统一读字段"，不新增工具/不改事件顺序/不动状态机迁移规则；改动收敛且可向前兼容。满足"真实严重问题＋已成定稿"；「与 Kimi/豆包讨论定稿」请主人确认闭环后执行。

**测试（改前后都跑）**：`_p5/_p6/_p7` 全测（尤其 _p7 的 SSE 事件序列与 payload 结构、set_status 唯一入口静态扫描、restore 中断恢复）；针对性：造一个 user_interrupt 终止任务，断言落盘含 terminate_kind；列表/详情/实时快照三读源字段一致；前端刷新/重拉后仍显「已被用户中止」。
