## 片3 执行与验收对照（网络调研固化，2026-09-05）
> 开工前必读。内容来自前端拆分/Alpine 官方与社区实测，转化为本项目可操作要点。

### 拆分路线已走对（勿改）
- 后端是 FastAPI「直接发 HTML」，**不引入 Vite/Webpack/构建工具**（违背档案派，且要「构建-部署」两套流程）。
- 大文件拆分最稳做法 = **整块搬、不拆逻辑、保持行为**；AI 直接拆大文件易断函数连接。3-A 先整搬 js 到 ch16-legacy.js 再章节拆分，正确。

### 执行时机（3-A 最关键）
- 原内联 `<script>` 在 body 尾（真实行号 L2289），拆到外部**放 body 尾、非 defer** `<script src=...>`，执行时机与原完全等价。
- ⚠️ **不得改成 `type="module"`**：本项目是经典脚本 + 顶层全局 `let/const` + 全局函数，module 的延迟执行/模块作用域会断裂 `$`/`state`/`providerIcon` 等全局绑定。保持经典脚本 + 顺序。

### Alpine 接入硬性要点（3-B/3-C）
- **`x-for` 必须每个都带 `:key`（唯一稳定值）**：不带 key 时以数组下标当 key，列表整体重赋值时 Alpine 以为没变 → 更新延迟/错位（GitHub alpine #4240）。3-C 已写「store 驱动 + :key 保活」，落实到**每个** x-for（含轮次索引）。
- **`x-cloak` 必须配全局 CSS** `[x-cloak]{display:none!important}`：只加属性不给 CSS 等于无效，会闪屏(FOUC)。`!important`+`display:none` 缺一不可。
- **流式正文用 textContent 追加、不碰 Alpine**（3-C 规则二）：避免高频响应式反复 diff。
- Alpine 3.17 x-for 已优化（PR #4361）：重渲同项提速 ~95%，增/删大列表显著提升 —— 正是替换全量 innerHTML 的价值，验收时对比。
- 全局共享数据用 `Alpine.store`（三域），组件内部用 `Alpine.data`；都走本地 vendor，残网可用。
